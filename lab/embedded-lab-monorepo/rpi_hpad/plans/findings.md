# Findings

## F001

No local `rpi_hpad` project existed yet under `/home/qiaopai`, so this work should be created as a separate project rather than mixed into the STM32/STC learning repo.

## F002

For this board, the most stable no-hardware architecture is interface-first:

- a single board abstraction
- `mock` and `replay` backends for current work
- a `real` backend placeholder that refuses use until SPI/GPIO integration is truly implemented

This lets services, CLI tooling, logging, tests, and ROS2-facing code stabilize before any ADS1256 timing or GPIO work starts.

## F003

`rclpy` is not installed in the current environment, so the ROS2 node must degrade gracefully.

Disposition:

- `ros2_pkg/analog_io_node.py` falls back to console JSON publishing instead of failing import-time.

## F004

On Debian 13 / Raspberry Pi environments with PEP 668 enabled, `python3 -m pip install -e .` against the system interpreter fails with `externally-managed-environment`.

Disposition:

- `scripts/check.sh` must validate packaging through a project-local virtual environment instead of assuming global editable installs are allowed.

## F005

`python3 -m app.main ...` requires an explicit module entry guard. Without `if __name__ == "__main__": raise SystemExit(main())`, subprocess-based packaging tests can appear to succeed with exit code 0 while producing no behavior.

Disposition:

- `app/main.py` now includes the module entry guard and is covered by `tests/test_packaging.py`.

## F006

For a software-first hardware-adjacent package, plain Python dict prints are not a stable UX surface. Status, sample, and completion outputs need one consistent, machine-readable format so CLI, tests, and future ROS/integration layers can all consume the same shape.

Disposition:

- CLI-facing commands now emit sorted JSON event records rather than ad-hoc Python repr output.

## F007

Logger and replay only become a real workflow when they share one file contract. A replay CSV should be directly generated by the logger, and light metadata can live in comment-prefixed lines without breaking standard CSV parsing.

Disposition:

- `AnalogService.log_to_csv()` now writes `rpi_hpad_csv_v1` metadata comments.
- `ReplayBoard` ignores comment-prefixed metadata lines and reads the same capture file directly.

## F008

Once the package starts behaving like a CLI product, `--help` and JSON output become part of the user-facing surface, not just incidental implementation detail. They need lightweight compatibility discipline.

Disposition:

- `hpad --help` now includes first-step guidance.
- CLI JSON output now uses `rpi_hpad_event_v1` with stable top-level fields and golden-style tests.

## F009

At this stage, the highest-value move is release freezing rather than more implementation. The software-facing contract is now more stable than the hardware assumptions, so continuing to add unverifiable driver detail would increase risk faster than value.

Disposition:

- Current milestone is frozen as `v0.1.0-soft-validated`.
- Hardware remains explicitly pending.
