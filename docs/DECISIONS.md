# Architecture Decisions

## ADR-001: 统一合并为单一仓库 `hardwire`
- **日期**: 2026-09-15
- **背景**: 用户在多设备实验管理（`muqiao-lab`）与硬件故障只读诊断（`device-doctor`）之间权衡，最终明确要求“一个仓库就可以，名字有点嵌入式的感觉最好”。
- **决定**: 将硬件资产快照、对比看板（Lab 面）与只读深度体检诊断（Doctor 面）合为一个项目 `hardwire`。
- **被否决方案**: 拆分为 `muqiao-lab` 和 `device-doctor` 两个独立仓库。
- **原因**: 避免配置和采集逻辑重复，同时维护一套无侵入探针逻辑足以支撑状态采集与故障定位。

## ADR-002: 无侵入（Agentless）采集架构
- **日期**: 2026-09-15
- **背景**: 目标设备多为小内存、低功耗或刚刷机的板卡（树莓派 5、ROCK 5C、老 x86），不适合长期部署重型 Agent 或守护进程。
- **决定**: 采用标准 SSH + 一次性只读管道，远程设备无需预装 Python 依赖或常驻 Daemon。
- **原因**: 保持板卡干净，随时接入，随时探测。

## ADR-003: IP 纯洁度、风控与解锁检测标准
- **日期**: 2026-09-15
- **背景**: 简单单源 API 查询无法反映翻墙/代理的真实风控现状（如黑五促销段 C 段污染、Cloudflare 盾、流媒体/AI 封锁）。
- **决定**: 严禁张口就来或使用单源简易 API。固定将开源权威工具 `IP.Check.Place`（xykt/IPQuality）作为唯一规范标准，集成进 `hardwire ip-check` 命令。
- **原因**: 具备 423 个黑名单库交叉比对、实机真实向流媒体/AI 鉴权端点握手验证，且生成防伪 SVG 报告，结论具备可复现的完整证据链。
